# Производительность навигации между вопросами

PostgreSQL benchmark сравнивает два варианта перехода между соседними вопросами на одинаковом тестовом наборе данных:

- `before` — прежняя последовательность callback-проверки, проверок ученика и прохождения, повторного чтения всех вопросов, сохранения позиции, загрузки ответа и истории попыток, а также формирования экрана с загрузкой полного LessonDetail ради метаданных урока;
- `after_warm_cache` — атомарная операция навигации в PostgreSQL, чтение опубликованных вопросов из прогретого ограниченного кэша, единый запрос сохранённого ответа и последней попытки и запрос только метаданных урока.

Оба варианта выполняются на локальной PostgreSQL изолированного CI job, с одинаковым учеником, опубликованной версией урока, двумя вопросами, сохранёнными ответами и попытками. Benchmark измеряет `ns/op`, аллокации и фактическое количество SQL-вызовов на один переход (`sql/op`). Подготовка данных и прогрев кэша не входят в измеряемый участок.

Запуск после применения миграций:

```powershell
$env:TEST_DATABASE_URL = "postgres://bible_app:password@localhost:5432/bible_platform_test?sslmode=disable"
cd backend
go test ./internal/repository -run '^$' -bench '^BenchmarkQuestionNavigationPaths$' -benchtime=30x -count=1
```

Числа времени зависят от CPU, задержек PostgreSQL и окружения, поэтому сравнивать следует оба подбенчмарка в одном запуске. `sql/op` — более стабильный показатель количества обращений к БД; `ns/op` отражает измеренную задержку на конкретном окружении.
