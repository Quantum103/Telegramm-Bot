# Автоматическая загрузка полных глав Библии и Telegraph

Telegram-бот получает полный текст Синодального перевода по требованию, сохраняет его в PostgreSQL и публикует главу в Telegraph. В вопросе остаются прежние элементы: вопрос, источник библейского отрывка, сам отрывок и подчёркнутая текстовая ссылка «Прочитать всю главу» внутри сообщения Telegram.

Mini App, WebApp и отдельный frontend для чтения Библии не используются.

## Режим загрузки

**Тексты глав не загружаются заранее целиком.** **При открытии вопроса внешние сервисы не вызываются.** Экран читает готовую главу из PostgreSQL и ищет постоянную Telegraph-ссылку по SHA256. Если подготовка ещё не завершена, ученик видит сообщение «Ссылка на полную главу готовится»; сам вопрос и сохранение ответа продолжают работать.

Подготовка выполняется фоновым worker. При публикации версии урока поддерживаемые ссылки на Синодальный перевод попадают в очередь в той же транзакции, что и публикация. При старте backend worker также добавляет в очередь ссылки из опубликованных и архивных версий — это покрывает уроки, опубликованные до установки очереди. Тексты глав не загружаются заранее: worker запрашивает только главы, на которые реально ссылаются материалы уроков.

## Источники и резервный порядок

### 1. Основной источник — Midvash

- Каталог книг: GET https://api.midvash.com/v1/books
- Глава: GET https://api.midvash.com/v1/synodal/{english_book_slug}/{chapter_number}
- При первом обращении Midvash каталог из 66 книг считывается для сопоставления канонического ID книги с английским slug и русским названием. Это метаданные каталога, а не загрузка текстов всех глав.
- Принимается версия **synodal**.

### 2. Резервный источник — GetBible

- Глава: GET https://api.getbible.net/v2/synodal/{book_id}/{chapter_number}.json
- Для Синодального перевода проверяются метаданные:
  - translation = Synodal Translation (1876)
  - abbreviation = synodal
  - lang = ru
- Сверяются номер книги, глава и номера стихов.

Источники вызываются **последовательно**, а не параллельно: текстовая идентичность их редакций не подтверждена. При недоступности, повреждённом JSON, неправильной версии или неполной главе Midvash сервис пробует GetBible. Если Midvash работает, а GetBible недоступен, основной источник продолжает обслуживать запросы — резервный источник для успешной загрузки не требуется.

Оба HTTP-клиента имеют тайм-аут запроса 8 секунд. Ответ ограничен 2 МиБ, проверяются HTTP-статус, UTF-8 и корректность JSON. Не прошедший проверку результат не сохраняется.

## Поведение при недоступности источников

- Если глава есть в PostgreSQL, она возвращается даже при недоступности обоих API.
- Если главы нет в PostgreSQL и оба API недоступны или возвращают некорректные данные, сервис проверяет встроенную локальную копию, если она есть.
- Локальная копия не записывается в **bible_chapters**, поскольку для неё нет метаданных подтверждённого внешнего источника.
- Для публикации Telegraph требуется сохранённая в PostgreSQL глава. Если её там нет, бот показывает безопасное сообщение о временной недоступности полной главы; обработчик Telegram не завершает процесс backend из-за этой ошибки.

## PostgreSQL и кеш Telegraph

Миграция **000006_bible_chapters** создаёт две таблицы:

- **bible_chapters** — один текущий сохранённый текст главы на комбинацию translation_code + book_id + chapter_number. Содержит JSONB со стихами, поставщика, версию, сведения об авторском статусе, SHA256 и время загрузки.
- **bible_chapter_telegraph_links** — постоянные ссылки на опубликованные статьи Telegraph, привязанные к переводу, книге, главе и SHA256 содержимого статьи.

### Очередь и фоновая публикация

Миграция **000015_bible_chapter_telegraph_jobs** создаёт устойчивую очередь подготовки глав. Уникальный ключ строки очереди — translation_code + book_id + chapter_number. Повторная публикация урока не создаёт вторую активную задачу; завершённая задача может быть снова поставлена в очередь, если опубликована новая версия урока.

Worker забирает задание коротким атомарным SQL-запросом с **FOR UPDATE SKIP LOCKED** и получает lease с уникальным токеном. Транзакция завершается до вызова Midvash/GetBible или Telegraph. В production worker ограничен двумя параллельными заданиями; тайм-аут одной задачи — 60 секунд, срок lease — 2 минуты. Ошибки повторяются с экспоненциальной задержкой от 5 секунд до 30 минут. Просроченный lease можно забрать повторно после аварии процесса.

Для публикации используется SHA256 сериализованных Telegraph Nodes. Таблица **bible_chapter_telegraph_links** имеет уникальный ключ translation + book + chapter + content SHA256. Перед внешним запросом worker проверяет существующую ссылку; после запроса сохраняет URL короткой отдельной SQL-командой. Транзакция или advisory lock не удерживаются во время HTTP.

У Telegraph нет API-ключа идемпотентности и общей транзакции с PostgreSQL. Поэтому невозможно гарантировать exactly-once при аварии в узком окне после успешного создания страницы, но до сохранения URL в PostgreSQL: в таком случае может остаться неиспользуемая страница. Обычные повторные задания и конкурентные worker защищены уникальной очередью и lease; после сохранения ссылки повторно используется одна и та же запись.

Старые URL-ссылки на Telegraph, уже отправленные пользователям в Telegram, продолжают открывать существующие статьи. Прежний RAM-кеш не содержал постоянных данных для переноса; исторические ссылки из старых сообщений не импортируются в новую таблицу автоматически.


## Формат ссылки и автоматический пересказ Telegram

Ссылка на полную главу отображается подчёркнутым текстом внутри сообщения Telegram, а не отдельной inline-кнопкой. Она использует обычную HTML-ссылку Telegram с подчёркнутым текстом. Для HTML-сообщений бот передаёт `link_preview_options.is_disabled = true`, поэтому Telegram не вставляет под вопросом карточку предпросмотра статьи с заголовком и фрагментом её текста. Сама ссылка остаётся рабочей. Остальные кнопки навигации и вариантов ответов не меняются.

Содержимое статьи Telegraph формируется только из текста стихов: каждый стих — отдельный обычный текстовый абзац с номером. Перевод не добавляется отдельной строкой, а номера стихов не выделяются жирным.

**Cocoon AI Summary нельзя отключить через код бота или Telegraph API.** Это автоматический блок самого клиента Telegram, который показывается сверху страниц Instant View. Он не хранится в статье и не передаётся нашим backend. Поэтому фактическое содержимое Telegraph остаётся обычным текстом Библии, но совместимый клиент Telegram всё равно может отдельно показать свой автоматический пересказ.

## Сопоставление BiblePassages

В **BiblePassages** остаются название книги, глава, диапазон стихов, необязательное название перевода и текст отрывка. Импортёр DOCX и модель учебного вопроса не менялись.

Для публикации полных глав бот сопоставляет название книги с традиционным порядком 66 книг. Матфея соответствует ID **40**. Если у отрывка явно указан другой перевод, он не подменяется Синодальным: ссылка на полную главу для неподдерживаемого перевода не создаётся. Если перевод не указан, используется подключённый Синодальный перевод.

Текст отрывка в экране вопроса берётся из существующего **BiblePassage.PassageText**; полная глава загружается отдельно. Поэтому отрывок и полная глава имеют разные назначения.

## Настройка Telegraph

Токен уже предусмотрен корневым **.env.example** и передаётся backend через **docker-compose.yml**. Новые переменные окружения для загрузки Библии не требуются.

1. Получите токен через [Telegraph createAccount](https://api.telegra.ph/createAccount).
2. Скопируйте **result.access_token** в корневой **.env**:

       TELEGRAPH_ACCESS_TOKEN=ваш_токен

3. Для работы текстовой ссылки также настройте **TELEGRAM_BOT_TOKEN**.
4. Пересоздайте backend после изменения **.env**:

       docker compose up -d --force-recreate backend

Токен — секрет. Не добавляйте его в Git, не включайте в скриншоты логов и не отправляйте в общие чаты. Если токен Telegraph отсутствует, учебный бот продолжает работать, но текстовую ссылку на полную главу не создаёт.

## Применение миграции

Миграции выполняются отдельным контейнером и **не запускаются автоматически при старте backend**. Перед обновлением существующей базы сделайте резервную копию.

Из корня репозитория:

    docker compose up -d postgres
    docker compose --profile tools run --rm migrate
    docker compose up --build -d backend
    docker compose ps

Инструмент применит все неприменённые миграции, включая:

- **000006_bible_chapters.up.sql** — создание таблиц глав и ссылок Telegraph;
- **000015_bible_chapter_telegraph_jobs.up.sql** — очередь подготовки полных глав;
- соответствующие файлы **.down.sql** — удаление таблиц при явном откате.

Откат удаляет сохранённые главы и ссылки. Не используйте migrate down как обычный способ обновления. Уже опубликованные миграции не редактируйте.

## Ручная проверка Матфея 4 в Docker Compose / PowerShell

Нужны Docker Compose, рабочие токены Telegram и Telegraph и опубликованный урок, в вопросе которого есть ссылка на Матфея 4. После применения миграций worker поставит ссылки из уже опубликованных и архивных версий в очередь автоматически.

### Запуск

В корне проекта:

    Copy-Item .env.example .env
    notepad .env

Укажите в **.env** локальный пароль PostgreSQL, **TELEGRAM_BOT_TOKEN** и **TELEGRAPH_ACCESS_TOKEN**, затем:

    docker compose up -d postgres
    docker compose --profile tools run --rm migrate
    docker compose up --build -d backend
    docker compose ps
    docker compose logs -f backend

После запуска backend в логах появится сообщение о запуске worker подготовки полных глав. Он подхватит очередь, которую заполнил backfill опубликованных уроков. До завершения работы worker вопрос открывается сразу и показывает сообщение «Ссылка на полную главу готовится».

Проверьте состояние задания:

    docker compose exec -T postgres psql -U bible_app -d bible_platform -c "SELECT translation_code, book_id, chapter_number, status, attempts, available_at, lease_until, last_error FROM bible_chapter_telegraph_jobs WHERE translation_code = 'synodal' AND book_id = 40 AND chapter_number = 4;"

После того как статус станет **completed**, откройте вопрос в Telegram ещё раз. В нём должна появиться прежняя подчёркнутая текстовая ссылка «Прочитать всю главу»; нажатие на неё открывает статью Telegraph.

### Проверка строки главы и ссылки

В другом окне PowerShell выполните:

    docker compose exec -T postgres psql -U bible_app -d bible_platform -c "SELECT translation_code, book_id, book_name, chapter_number, source_provider, source_version, jsonb_array_length(verses) AS verse_count, content_sha256, fetched_at FROM bible_chapters WHERE translation_code = 'synodal' AND book_id = 40 AND chapter_number = 4;"

После завершения фоновой подготовки ожидается одна строка с **book_id = 40**, **chapter_number = 4**, **source_provider = midvash** или **getbible** и положительным **verse_count**.

Проверьте постоянную ссылку:

    docker compose exec -T postgres psql -U bible_app -d bible_platform -c "SELECT translation_code, book_id, chapter_number, content_sha256, page_url, created_at FROM bible_chapter_telegraph_links WHERE translation_code = 'synodal' AND book_id = 40 AND chapter_number = 4;"

Откройте тот же вопрос ещё раз. Запрос должен получить главу из PostgreSQL и вернуть уже сохранённый Telegraph URL. Для проверки перезапуска:

    docker compose restart backend

После запуска откройте вопрос снова и повторите SQL-запрос. Для одной и той же версии содержимого ссылка должна остаться той же, а число строк в таблице ссылок не должно увеличиться.

**Не удаляйте строки из основной базы ради повторного вызова API.** Если Матфея 4 уже сохранена, описанная проверка подтверждает путь кеша, а не холодную загрузку. Для отдельного холодного теста используйте изолированную базу и временно направьте backend на неё через переменную **POSTGRES_DB**, как показано ниже.

### Холодный запуск в отдельной тестовой базе

Эти команды создают дополнительную базу внутри локального контейнера PostgreSQL. Они не очищают **bible_platform**:

    docker compose exec -T postgres createdb -U bible_app bible_chapter_sandbox
    $env:POSTGRES_DB = "bible_chapter_sandbox"
    $env:MIGRATIONS_DATABASE_URL = "postgres://bible_app:URL_ENCODED_PASSWORD@postgres:5432/bible_chapter_sandbox?sslmode=disable"
    docker compose --profile tools run --rm migrate
    docker compose up -d --force-recreate backend

Затем откройте в Telegram вопрос со ссылкой на Матфея 4. Backend будет читать и сохранять главы в **bible_chapter_sandbox**. Проверка SQL выполняется той же командой, но с **-d bible_chapter_sandbox** вместо **-d bible_platform**.

Чтобы вернуть backend на основную локальную базу:

    Remove-Item Env:POSTGRES_DB
    Remove-Item Env:MIGRATIONS_DATABASE_URL
    docker compose up -d --force-recreate backend

Не удаляйте тестовую базу до проверки её содержимого, если хотите сохранить результаты эксперимента.

## Go-тесты и безопасность TEST_DATABASE_URL

Unit-тесты не требуют внешних API и используют **httptest**. Проверки реальных SQL-запросов требуют отдельной тестовой PostgreSQL с применёнными миграциями.

**Важно:** интеграционный helper использует TRUNCATE ... CASCADE для таблиц учеников, курсов и уроков. Не задавайте **TEST_DATABASE_URL** на **bible_platform**, на рабочую базу или на базу с пользовательскими данными.

Для Windows PowerShell создайте отдельную базу:

    docker compose exec -T postgres createdb -U bible_app bible_platform_test
    $env:MIGRATIONS_DATABASE_URL = "postgres://bible_app:URL_ENCODED_PASSWORD@postgres:5432/bible_platform_test?sslmode=disable"
    docker compose --profile tools run --rm migrate
    Remove-Item Env:MIGRATIONS_DATABASE_URL

    $env:TEST_DATABASE_URL = "postgres://bible_app:URL_ENCODED_PASSWORD@localhost:5432/bible_platform_test?sslmode=disable"
    Push-Location .\backend
    gofmt -w .\cmd .\internal
    go test ./...
    go vet ./...
    Pop-Location
    Remove-Item Env:TEST_DATABASE_URL

Замените **URL_ENCODED_PASSWORD** на URL-кодированный пароль. **TEST_DATABASE_URL** указывает на localhost, поскольку Go-тесты запускаются в PowerShell на хосте; **MIGRATIONS_DATABASE_URL** использует имя сервиса postgres, поскольку мигратор запускается внутри Docker-сети.

В CI переменная **TEST_DATABASE_URL** указывает на отдельный временный PostgreSQL-контейнер. Если **TEST_DATABASE_URL** не задана локально, интеграционные тесты пропускаются; go test ./... всё равно запускает остальные тесты.

## Что проверяют автоматические тесты

- чтение сохранённой главы без вызова источников;
- первичный Midvash и резервный GetBible;
- переход к GetBible при повреждённом JSON Midvash;
- отклонение неподходящего перевода, версии, книги/главы, неполной главы и неверной нумерации;
- контролируемую недоступность при отсутствии сохранённой и локальной главы;
- подавление одновременных загрузок одной главы внутри экземпляра сервиса;
- повторное использование Telegraph-ссылки, конкурентное создание ссылки и сохранение главы/URL в PostgreSQL между экземплярами репозитория;
- совместимость Telegram-экрана, исходного отрывка и подчёркнутой текстовой ссылки.

Автоматические тесты с **httptest** не обращаются к реальным Midvash, GetBible или Telegraph. Реальное первое получение Матфея 4 проверяется описанным холодным запуском; сбои внешних API моделируются тестами, а не отключением реальных сервисов.
